# New Assumptions Module

- Francesco built a “typeless” assumptions system: uses inequalities and set-membership statements instead of Q.* predicates
  - x > 0 replaces Q.positive(x); x ∈ Integers replaces Q.integer(x)
  - Allows richer constraints like x > 2 given x > 1, which current SymPy cannot handle
- Tilo skeptical Fable can get assumptions to full production quality
  - Ran comparison: SymPy Extras assumptions ~34s vs. new assumptions ~30s on passing tests; both considered too slow
- Discussion on API design:
  - Old assumptions: clean syntax, but three-valued logic limits combining facts before query
  - New assumptions: more expressive, but slower and harder to use internally
  - Tilo’s suggestion: separate developer-facing API (optimized, verbose) from user-facing API (simple)
- Consensus: rewriting the SymPy core to fix performance is too risky given downstream library breakage
  - ProtoSym (Oscar’s project) flagged as the right direction for a fast, non-simplifying expression tree for internal use
