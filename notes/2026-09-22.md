# Benchmarking and Cache Behavior

- ASV benchmark cache-clearing is not handled correctly in current SymPy benchmarks
  - setup runs before each repeat, but not before each number iteration
  - Fix: set number=1 and clear cache in setup (ASV auto-sets number=1 when a setup hook exists)
- Multiple caches to consider:
  - sympy.core.cache manages most caches via clear_cache()
  - New assumptions system uses a separate memoize property (stores forever, no LRU)
  - Memoization (e.g. prime sieve, partition function) is distinct from caching and never cleared
- Memoization-forever flagged as a flaw: problematic for long-running servers accumulating memory
