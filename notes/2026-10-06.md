# AI-Generated PR Spam: Root Causes

- Core workflow disruption from AI-generated pull requests is the primary problem
- Debate on whether GSoC participation is the main cause (Oscar’s view) vs. other factors (Francesco’s view)
- Pattern: contributors find a random open issue, point an AI agent at it, submit without understanding the problem
- SymPy specifically targeted: pure Python, easy to contribute to, well-known, LLMs likely recommend it heavily
- Lean4 Mathlib comparison: 1,400 open PRs but stricter formal verification acts as a natural quality gate

# Detecting AI-Generated Content

- Pangram AI detector: tested live during the meeting, flagged a recent PR as 100% AI-generated
  - Free tier available; developer API is credit-based (~5 cents per 100 words)
  - $60/month plan includes $200 in API credits (~400,000 words/month)
  - No good open-source alternative identified
- GitHub audit log reveals whether a PR was opened via CLI, API, or browser
  - Only org admins can access it; Aaron built a browser extension to surface this data on the PR list
  - Some agents (OpenCode, Codex) self-identify in the audit log
  - MuseSpark (Meta’s autonomous agent) confirmed on one flagged PR
- OpenAI and Anthropic reportedly adding token-level watermarking, but won’t cover open-source models
- AI disclosure in agents.md is being followed by some, ignored by fully autonomous runs

# Proposed Barriers and Filters

- Require issue comment before opening a PR (signals genuine engagement)
- Bot-based filtering using multiple signals (CLI use, API origin, Pangram score), not a hard rule
  - Don’t publicize the exact signals to avoid gaming
  - Close PRs with failing tests automatically (already partially in place)
- Restrict new contributors from opening PRs until they’ve reviewed others or engaged in the issue tracker
  - Risk: AI can also generate fake reviews and comments
- Video call requirement floated but rejected: too high a barrier, filters good contributors too
- Vouch system (Tilo’s suggestion): a maintainer runs a command to vouch for a contributor; vouched users get full access
  - Tilo has looked into it briefly; appears configurable
  - Aaron skeptical it will work at scale without broad adoption

# agents.md Prompt Hardening

- Current agents.md tells agents not to auto-open PRs; some agents ignore it or run fully autonomously
- Tilo tested framing auto-PR submission as “unethical” in the prompt: agents refused due to safety training
- Proposal: update agents.md to refuse writing the PR description or opening the PR entirely
- Risk to avoid: accidentally blocking legitimate SymPy developers using AI tools
- Sangyub’s view: an unconditional rule is simpler and more robust than one with exceptions

# Assumptions System and New Syntax

- Tilo shared benchmarks comparing SymPy’s new assumption system, Francesco’s extras package, and the old system
  - New system is fast; extras is a separate package with significant shared code
  - Integration with other parts of the assumption system is still “janky”
- Syntax debate: Q.positive(x) vs. positive=True vs. Contains(x, Reals)
  - positive=True seen as most natural Python; Q.positive reverses the natural reading order
  - Contains prints nicely but is verbose to type
  - Variables not assumed real by default limits inference; edge cases around NaN and extended reals remain tricky
- Sangyub raised formal semantics gap: real, extended real, complex, and float each have different analytic properties that the assumption system conflates

# Lean Formalization Experiments

- Sangyub formalized the Routh-Hurwitz algorithm entirely in Lean using AI
  - Lean code AI-generated; translated verbatim from SymPy’s Python implementation
  - Proof verified: zero bugs found across all tested inputs
- Workflow: AI translates SymPy code to Lean, generates correctness proof, constrains algorithm shape
  - Once proven correct, AI can safely experiment with data structures and optimizations
- Suggested starting point for broader effort: polynomial algorithms, where mathematical rigor matters most
- Caveat: not proposing everyone learn Lean; goal is to leverage tools for targeted high-value proofs
