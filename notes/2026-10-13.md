# GSoC AI Spam Problem

- Core issue: volume of AI-generated PRs is unmanageable, drowning out genuine contributors
- Default position: not applying for GSoC next year unless a workable filter is found
  - Application deadline likely end of January; decision needed by year-end
- Consensus: AI use isn’t the problem, lack of engagement and code understanding is
  - Bad actors: submitting agent-generated PRs without reviewing output or responding to comments
  - Good contributors still exist but get lost in the noise

# Francesco’s AI Detection Model

- Built a classifier on PRs from 2018–2022 (pre-AI baseline) vs. Claude-generated equivalents
  - Method: TF-IDF vectorization of 2–6 character substrings, logistic regression
  - 5-fold cross-validation; threshold set at ~1% false positive rate
- Performance on recent PRs: ~40% false negative rate, detection near random on AI-declared PRs
- Notable finding: test_ prefix in PR descriptions is a strong predictor of AI authorship
  - Claude routinely lists added test functions in descriptions; humans don’t
- Model trained on Claude output only; doesn’t generalize well to other models

# Pangram and Commercial Detectors

- Pangram tested on Claude-prompted-to-sound-human text: caught only 2 of 4 samples
- University of Chicago audit reportedly found near-zero error rate on standard AI text
- Key concern: false negative rate on prompted/human-sounding AI text is unknown
- Pangram has published research papers, including detection of AI-edited human text
- Cost and opacity of API make independent validation difficult

# Proposed Shift in GSoC Evaluation Criteria

- Proposal: weight code review and community interaction over PR authorship
  - Opening a PR is no longer a meaningful filter; reviewing one still is
  - Suggested new requirement: at least one substantive review of someone else’s PR
- Signals of a good contributor:
  - Commenting on issues, reviewing PRs, responding to feedback
  - Evidence of critical engagement with AI-generated output, not just submitting it
- Any metrics used must stay private; publishing them invites gaming

# Contributor Dashboard Idea

- Build a private dashboard aggregating GitHub activity per contributor:
  - PRs opened, PRs commented on, issues opened, responses to review comments
  - Optional: AI vs. human text score per comment (via model or Pangram)
- Goal: surface high-signal contributors buried in noise, not enforce rules
- Easy to prototype with GitHub API; Claude can scaffold it quickly
- Francesco also suggested a bot that scans new contributor comments weekly and scores human vs. AI writing
