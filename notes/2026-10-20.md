# AI-Detection Model (Franz)

- V3 model: n-gram logistic regression on PR description text
  - Breaks text into substrings, assigns frequency vectors with statistical renormalization
  - Scores 0–1; flagged above threshold (e.g. 0.403 for V3)
  - Key signal: AI descriptions include full file paths and test file references; humans rarely do
  - Word-level contributions visible in UI (red = AI-leaning, blue = human-leaning)
- Dataset: PRs from 2018–2022 (human-written) paired with Claude-regenerated AI-style equivalents
  - AI style derived from 2026 PRs that explicitly disclosed AI authorship
- Refined performance estimates (V3, 80+ word PRs, 1% threshold):
  - Precision 0.96, recall 0.85–0.87, specificity 0.97
  - ~3% false positive rate; ~15% false negative rate
- Results by disclosure group (V3 flagged rates):
  - Explicitly AI-written: 88–100% flagged (strong signal)
  - No AI use declared, members: 0% flagged
  - No AI use declared, returning contributors: 10% flagged
  - No AI use declared, first-time contributors: 47% flagged; no-association: 63% flagged
  - Interpretation: significant share of first-timers likely lying about AI use

# Spam PR Strategy

- Consensus: close stale AI-generated PRs, not ban contributors
  - Most spammers are one-time contributors who disappear anyway
  - Banning only warranted for persistent harassment
- Franz’s proposed policy: 3-month grace period for new PRs
  - After 3 months with no reviewer engagement + AI-flagged description: close silently
  - Human-written PRs get a longer open window
- Sangyub’s view: maintainers should moderate more aggressively and subjectively now
  - No need to wait for automation; human judgment is sufficient and appropriate
  - Closing unconditionally is fine; scientific precision not required
- Aaron’s view: requiring issue comment before opening a PR could reduce spam significantly
- Goodhart’s Law concern: all metrics and thresholds must stay private
  - If detection criteria leak, contributors will prompt AI to evade them

# GSoC Rules

- Current problem: spam volume makes GSoC unworkable without aggressive filtering
  - Need to close the majority of bad PRs immediately, not after a grace period

  - AI forbidden for PR descriptions and GitHub comments by GSoC applicants
  - AI-generated code still permitted
  - Even stylistic AI rewrites forbidden (grammar corrections currently allowed)
